# `senses_i18n/` — per-language translations of the polysemous sub-senses

Localizes the Hebrew-context **sense** labels (`../hbo_lex.tsv`) beyond the dominant sense.

## What's already free (no files here needed)
The **dominant** sense of each `(lex, stem)` localizes automatically: shoresh `_lex_senses`
relabels it with the per-stem gloss from `word_glosses/hbo/<Language>.csv` (12 languages). That
covers the **72%** of `(lex, stem)` that are single-sense outright, plus the primary sense of the
polysemous ones. Nothing to translate for those.

## What this folder is for
Only the **non-dominant** senses of polysemous `(lex, stem)` stay English. Those are the gap:
- **`_gaps.tsv`** — the worklist (regenerated by `bcv-RAG/scripts/build_sense_gaps.py`):
  `lex · stem · sense · en_gloss · share`. **4,513** senses across **2,211** polysemous `(lex,stem)`.
- **`<iso639-3>.tsv`** — a language's translations: `lex · stem · sense · gloss` (same key columns
  as `_gaps.tsv` + the translated `gloss`). One file per language (scalable — like
  `../../semantic_domains/domain_labels/`, `../../concept_surfaces/`). None committed yet; add them
  as languages get translated.

## To localize a language
1. Take `_gaps.tsv` rows, translate the `en_gloss`, write `<iso639-3>.tsv`
   (`lex · stem · sense · gloss`) — e.g. `deu.tsv`, `ind.tsv`. Give it a `# source/license` header.
2. That's it. shoresh `_sense_i18n(<iso>)` reads it; `_lex_senses` applies it to the sub-senses,
   falling back to English where a row is absent. The gloss-language NAME→iso639-3 map lives in
   shoresh `data.py` (`_GLOSS_LANG_ISO`).

Same "author the translations, key by the stable id" pattern as the domain labels — just a bigger
(4.5k vs 664) and lower-priority worklist (sub-senses are the long tail of polysemy).
